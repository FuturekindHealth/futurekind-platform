# Research Handbook

Part 11: publication-quality output produced by the instrument that made it, not assembled afterwards
in a spreadsheet. Everything here is generated by
`python -m evidence tables|figure|check` against a session store that lives outside the repository,
and the point of that arrangement is that a paper's Table 1 and its raw data come from the same code.

**State: C throughout.** No study has been run, so nothing in this file has produced a result. What
exists is the machinery and the rules for using it honestly.

---

## 1. The pipeline, in the order a reviewer will ask for it

| Step | Command | Output |
| --- | --- | --- |
| Baseline characteristics | `python -m evidence tables --store F --success FIELD` | `table_1()`: counts per `modality`, `category`, `difficulty`, `site`, `role`, plus the `time_to_final_seconds` distribution |
| Outcomes | same | `results_table()`: per-stratum rate with a Wilson interval and its `n` |
| Anonymisation gate | `python -m evidence check --store F` | offenders, `cells_below_k`, `k_min`, and a verdict that is `"refused: ..."` while anything remains |
| Between-site view | same | `centre_summary()`: per-site rates, heterogeneity as a spread of rates, never a pooled effect |
| Figure | `python -m evidence figure --store F --metric M [--period month] --svg` | A trend series with `n` printed at every point, or an SVG with the same discipline |
| Export | `reporting.write_csv(rows, path)` | A CSV outside the repository; it raises if the path is inside one |

`--success FIELD` is required rather than assumed. Deciding what counts as the success event is a
study-design choice, and a tool that picks it silently has written the conclusion into the pipeline.

## 2. Statistics, and why each one was chosen

`evidence/stats.py` is stdlib-only, which is a research decision, not a limitation:

| Used | Instead of | Because |
| --- | --- | --- |
| Wilson score interval | the normal-approximation Wald interval | Wald reports an interval touching zero for 1 success in 10 cases. That is the sentence that becomes "no harm observed" |
| Exact McNemar, via the binomial as-or-less-probable tail | chi-square McNemar | Twenty-case pilots have two or three discordant pairs. An approximation on that data is arithmetic nobody can check, and the exact version is a sum a reader can do by hand |
| Sign test, and Wilcoxon signed rank with tie and continuity corrections | a paired t-test | Review seconds are not normal. One forty-minute report must not set the mean of a department |
| Wilcoxon **refused below n = 10** | a p-value that looks fine | The normal approximation's own floor, stated in the returned `caution` |
| Percentile bootstrap with a published seed | an asymptotic interval | Reproducible: a reviewer can re-run it and get the same numbers. The seed is `20261009` and travels in the method string |
| Holm step-down | no adjustment | It is monotone, provable by a test, and conservative enough for a study with one primary endpoint |
| `mde_paired`, printed on every gate row | silence about power | "No difference" from an underpowered sample is read as evidence of safety, which is the most expensive misreading in clinical software |

**Not used:** any Bayesian model, any meta-regression, any machine-learning classifier. Each would
let a handful of points look like a finding, and a paper whose statistics cannot be re-derived with
a pen and a printed critical-value table is a paper a hospital cannot audit.

## 3. What a reviewer will ask, and where the answer already is

| Question | The answer this system produces |
| --- | --- |
| "How did you choose the primary endpoint?" | `stats.Preregistration.signed_by`, `primary_endpoint` and the date. An incomplete registration returns `analysed: false` with the list of problems |
| "How many analyses did you run?" | Every endpoint is marked `primary: true/false`, and anything beyond the registration carries `multiplicity_warning` and the Holm-adjusted values |
| "What was the case mix?" | `case_mix` beside every aggregate; `longitudinal.case_mix_drift` between periods |
| "Is the reference standard trustworthy?" | [`GROUND_TRUTH.md`](GROUND_TRUTH.md) §4: today, `ratified_and_valid: 0` out of 100. The honest citation is that sentence, not a description of the dataset's design |
| "What is n?" | Printed with every rate and every figure point. `svg_line` refuses to draw a line through fewer than two periods, and prints `(n=…)` at each one |
| "Could a patient be re-identified?" | `anonymise_check` before any export: identifier-shaped values, stored text, and quasi-identifier cells below `K_MIN = 5` |
| "Were the models real?" | `store.real_rows()` excludes stub-provenance rows from every aggregate, and `loop-state` prints what has actually been measured |

## 4. Reporting rules for any write-up

1. **Six axes, never a composite.** A "FutureKind score" is not a thing this platform produces
   ([`METRICS.md`](METRICS.md) §5), and a reviewer who asks for one is asking for a claim the data
   cannot carry.
2. **Every number carries its state** ([`FRAMEWORK.md`](FRAMEWORK.md) §3). A capability is not a
   result, and a measured number is not one about care unless the case was ratified.
3. **Denominators, not adjectives.** "Substantially faster" is not in this vocabulary; `median 0.4×`
   with its interval and its `n` is.
4. **Name what was excluded.** `RegressionReport.excluded` counts rows without a pair; a table that
   drops cases must say how many and why, or the denominator is a selection effect.
5. **Quote the limitations beside the number, not in a footnote.** `evidence.baseline` prints its own
   four limitations inside its output for exactly this reason, and generated tables keep them attached.

## 5. Reproducibility, as a checked property

A published figure must be regenerable from the store plus a command. Three things make that true
rather than merely claimed:

- Fixed, published seeds in every bootstrap.
- Deterministic allocation in experiments, so a stranger can re-derive the arms ([`EXPERIMENTATION.md`](EXPERIMENTATION.md) §2).
- Generated artefacts marked as generated: [`BASELINE.md`](BASELINE.md) and
  [`ERROR_TAXONOMY.md`](ERROR_TAXONOMY.md) each begin with the command that produced them
  ([`../README.md`](../README.md) §10 rule 2).

If a paper cites a FutureKind number, the citation chain should run: paper → dated table → generating
command → instrument → test that proves the instrument computes what it says.

## 6. What this handbook does not promise

No statistical library, no effect-size meta-analysis, no natural-language generation for the
discussion section. A paper's argument is written by its authors; this machinery's job is that the
numbers in it cannot be quietly re-picked.

## 7. Drift check

The check that fails when this file drifts is `python -m evidence selftest` plus the stats and
reporting blocks in `test_evidence.py`: `test_wilson_interval_known_answer`, `test_mcnemar_known_answer`,
`test_wilcoxon_refuses_a_sample_too_small_for_its_approximation`, `test_bootstrap_is_reproducible`,
`test_holm_is_monotone_in_the_adjusted_values`, `test_svg_prints_the_denominator`,
`test_svg_refuses_to_draw_a_trend_from_one_point` and `test_thin_cells_are_flagged_before_export`. The
bootstrap seed named in §2 is read from `stats.bootstrap_paired`'s default argument, so a changed
seed makes this file wrong on its own line.
