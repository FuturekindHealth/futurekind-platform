# Clinical Benchmark Framework

Part 7: what a benchmark is in this platform, which ones exist, and what it takes to promote one.
A benchmark here is **not** a leaderboard of models. It is a department's own ratified cases plus a
fixed endpoint plus a pass rule that was written before the run — the combination that lets someone
say "this application is adequate *for us*".

---

## 1. The four parts of a benchmark

| Part | Where it lives | What disqualifies the benchmark without it |
| --- | --- | --- |
| Ratified cases for *that* department | [`GROUND_TRUTH.md`](GROUND_TRUTH.md), `evidence/groundtruth.py` | Synthetic, engineer-authored cases prove the instrument, not the care — which is all 100 today |
| Endpoints chosen before the run | `evidence/stats.py` `Preregistration`; [`EXPERIMENTATION.md`](EXPERIMENTATION.md) §4 | An endpoint picked after the data is a description of the data |
| A pass rule with a denominator | [`METRICS.md`](METRICS.md) §3, `regression.DEFAULT_ENDPOINTS` | A threshold with no measured false-positive cost is an opinion (`../safety/CLINICAL_SAFETY.md` §6 gate G2) |
| A named owner | `../GOVERNANCE.md`, and gate G5 — a named risk owner | Nobody can be asked why it changed |

The four match the four tests every application must pass
(`docs/product/PRODUCT_BIBLE.md:19`), applied to evaluation instead of construction: a benchmark that
requires a platform change to run is a benchmark that will not survive a second department.

prostate, liver or bone-density service does not — and the gateway already authorises a pathology

## 3. What transfers between benchmarks, and what does not

| Transfers | Does not transfer |
| --- | --- |
| The instruments: `edits`, `stats`, `scoring`, `store`, `regression`, `experiment`, `longitudinal`, `loops`, `reporting` | The reference answers. A pathology case is a different document with a different notion of "supported" |
| The taxonomy's *structure* — four groups, an observable per class | `E04 wrong_laterality`, which is nearly meaningless on a whole-slide image, and `E05 wrong_anatomy`, which means something entirely different there |
| The refusals: no composite, no auto-apply, no store inside the tree | The nine engine checks, all of which were tuned against imaging dictation |
| The protocol shape ([`PROTOCOL.md`](PROTOCOL.md)) | The pre-registered endpoints: turnaround is a radiology quantity; a pathologist's benchmark asks about reporting completeness and consensus |

This is the same finding [`../product/CLINICAL_SUITE.md`](../product/CLINICAL_SUITE.md) §3.3 reaches
from the product side, and the two agree: what is reusable is the machinery and the discipline, not
the content.

## 4. Promoting a benchmark

A benchmark moves up one rung only when the rung below it has an artefact, which is the gate
discipline of `docs/safety/CLINICAL_SAFETY.md:129` applied to evaluation:

| Rung | Requirement | Artefact | Current occupants |
| --- | --- | --- | --- |
| 0 Designed | Endpoints and pass rule written down before any run | A `Preregistration` with an owner | Radiology brain reporting |
| 1 Authored | Cases exist, structurally valid | `python -m evidence groundtruth` with `with_validation_problems: 0` | Radiology (100), and nothing else |
| 2 Ratified | A clinical role, not the author, signs each case | Signed case files outside the tree | **None** |
| 3 Measured | A real model and a real clinician, with the regression gate run | A dated table, generated by a command | None |
| 4 Published | Internally or externally readable, with limitations attached to the numbers | A dated report in `docs/` | None |

Radiology sits at rung 1. Everything else sits at rung 0, which is the honest answer to "how far
along is FutureKind clinically": the instruments are built, one department's corpus is authored, and
nothing has been ratified or measured.

## 5. The smallest new benchmark worth building

Twenty ratified cases, in this order of value:

1. **MRI brain, ratification only** — the cases exist and the workflow is built; the missing act is a
   consultant's signature on twenty of them, which is the cheapest move from rung 1 to rung 2 and
   the same afternoon as [`PROTOCOL.md`](PROTOCOL.md) §5.
2. **Pathology, whole-slide reporting** — the skill is already authorised
   (`core/gateway/models.yaml:68`) and calls nothing, so a benchmark here also decides whether that
   skill stays. Its document model does not exist yet, so this costs authoring, not ratification.
3. **Discharge summaries** — the ward workflow is the second-highest drafting load in
   `docs/clinical/HOSPITAL_WORKFLOW.md`, and its evidence base is zero, so any number there would be
   the first.

Each needs its own `expected_sections`, its own difficulty spread and — the part people skip — its
own measured false-positive cost before a severity is chosen. A severity imported from radiology is a
guess wearing another department's measurements.

## 6. What a benchmark must never become

- **A hospital leaderboard.** Comparing installations is restricted by P14
  (`docs/CONSTITUTION.md:335`) and analysed in [`ANALYTICS.md`](ANALYTICS.md) §5.
- **A model race.** ADR-0002 rule 1 keeps model choice out of the application boundary, so a
  benchmark that names models invites the platform's own south border to be argued about in public
  using numbers it did not produce.
- **A single number.** Six axes, no composite ([`METRICS.md`](METRICS.md) §5). A benchmark with one
  score is a benchmark whose worst axis is invisible.
- **A fixed threshold that nobody may question.** Thresholds are governance
  ([`../GOVERNANCE.md`](../GOVERNANCE.md)); a paid tier may add a service and may never move one.

## 7. Drift check

The check that fails when this file drifts is `test_engine_check_ids_match_the_product_exactly` (the
nine checks in §3 are the product's, not a copy) plus `python -m evidence taxonomy` and
`python -m evidence baseline`, which print the coverage and modality figures in §2. The skill names
and their line numbers are read from `core/gateway/models.yaml`, and the corpus counts are generated
by the same command that produced [`BASELINE.md`](BASELINE.md) — so if this table disagrees with that
file, this table is the defect.
